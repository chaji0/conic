## 좌표계 (가장 중요)

- **+x = 동쪽, +z = 남쪽, +y = 위**
- 미니맵은 `N`을 위쪽에 그리며 화면 y가 커질수록 z가 커집니다(= 남쪽).
- 지도는 북쪽 끝 `z = -140`(도곡역이 있는 가로 도로)부터 남쪽 끝 `z = 110`까지 뻗어 있고,
  `x = 0`에 남북을 관통하는 중앙 간선도로(스파인)가 있습니다.
- 주요 지점은 전부 `NODES` 객체에 모여 있습니다. 좌표를 바꿀 일이 있으면 반드시 `NODES`를 고치고,
  그 값을 참조하는 `MM_LANDMARKS` / `zonesForLabel` / `carPaths` / 건물 `position.set` 을 함께 확인하세요.

### 그룹 회전 트릭 (단대부고)
단대부고는 내부 좌표를 그대로 두고 그룹만 `rotation.y = SCHOOL_ROT (= -π/2)` 로 돌려
정문이 동쪽을 보게 만들었습니다. 따라서 **학교 내부의 로컬 (x, z)를 월드로 바꿀 때는**

```
world.x = NODES.schoolGate.x - localZ
world.z = NODES.schoolGate.z + localX
```

이 매핑을 써야 합니다. 파라볼라 마이크 조준(`MIC_AIM.worldPos`)과 운동장 선수 위치
(`updateSchoolRunner`)가 이 변환에 의존하므로, 학교 안 오브젝트를 옮길 때 같이 확인하세요.

## 도로 시스템

`roadSegment(a, b, width)` 는 **그리지 않고 정의만** `ROAD_DEFS`에 쌓습니다.
모든 `roadSegment` 호출이 끝난 뒤 `buildRoads()` 가 한 번에 그립니다. 이 순서를 바꾸면 안 됩니다.

`buildRoads()` 가 하는 일:
1. 도로 바닥
2. **인도** — 짧은 칸으로 나눠 다른 도로를 가로막는 칸만 빼고, 남은 칸은 연속 구간끼리 병합해 그림
   (432칸 → 29개 메시). 교차로가 뻥 뚫려 보이는 이유입니다.
3. 노란 중앙선 — 교차로 안에서는 끊김
4. **회전 유도 점선** — 삼거리/사거리마다 진입 차선 → 진출 차선을 잇는 흰 점선

교차로 판정 함수: `insideRoad`, `nearlyParallel`, `blockedByOther`.

> ⚠️ 인도를 지우는 범위(`blockedByOther(def, x, z, 2.8, 0.6)`)의 마지막 인자(길이 방향 여유)를
> 키우면 **T자 교차로에서 건너오지도 않는 반대편 인도까지 지워집니다.** 실제로 그 버그가 있었고
> 0.6으로 낮춰 고쳤습니다. 건드리지 마세요.

도로 접합점 탐지는 끝점끼리 비교하는 것만으로는 부족합니다(도로 *중간*에 다른 길이 붙는 T자를 놓침).
`buildRoads` 4단계의 후보 탐색 로직을 참고하세요.

**차량 우측통행**: `updateCars` 에서 진행 방향의 오른쪽 벡터 `(-fz, fx)` 방향으로
`car.userData.lane`(2.0~2.2)만큼 밀어서 그립니다. 코너에서 튀지 않도록 오프셋과 회전 모두 프레임 보간합니다.

## 이차곡선 물리 모델 (수업의 핵심이라 임의로 바꾸지 마세요)

공통 아이디어: **초점에서 반사면이 차지하는 입체각의 비율** `(1 - cos φ) / 2` = 모아지는 빛의 양.

### 자동차 / 자전거 전조등
```
depth = R²/(4p)
φ     = atan2(R, p - depth)        // 꼭짓점 방향 기준 테두리까지의 반각
밝기  = (1 - cos φ) / 2
퍼짐각 = 전구반지름 / p             // 전구가 점이 아니라서 생기는 발산
```
반사판이 깊어져도(작은 `p`) **렌즈 면은 제자리**에 있고 꼭짓점만 차 안쪽으로 들어갑니다
(`dish.position.x = rimX - depth`). 전구는 항상 초점 위(`rimX - depth + p`)에 놓입니다.

### 태양열 집광장치 (`SOLAR`)
흡수기는 꼭짓점에서 **고정 높이 H = 6** 인 탑 위에 있습니다.
```
spot = |R·(p - H) / (p - depth)|          // 흡수기 높이에서의 빛 반경
eff  = 1 / (1 + (spot/3)²)
cityPower = 0.25 + 0.75·eff
```
`p = 6`(= H)일 때 효율 100%. 슬라이더 범위는 4.5~10인데, **4.5 아래로 내리면 `p - depth`가
0을 지나며 발산합니다**(초점이 반사판 테두리 평면에 놓이는 지점). 하한을 낮추지 마세요.

`cityPower`는 밤 조명 밝기에 그대로 곱해집니다.

### 카세그레인식 반사망원경 (`TELE`)
주경 = 포물면(초점거리 `fp = 3.2`), 부경 = 아래로 볼록한 쌍곡면.
부경 꼭짓점에서 가까운 초점까지 거리 `s = 1.0`, 슬라이더는 부경 위치 `d`.
```
d + s = fp  (즉 d = 2.2) 일 때 두 초점이 겹쳐 상이 맺힘
sharp = exp(-(|(d+s) - fp| / 0.30)²)
```
팝업의 은하수는 캔버스로 직접 그린 뒤 `filter: blur((1-sharp)*10px)` 로 흐리게 합니다.

## 밤낮 주기

`DAY_LEN=60, DUSK_LEN=30, NIGHT_LEN=60, DAWN_LEN=30` (총 180초).
`computeDayFactor(t)` → 0(한밤)~1(밝은 낮). `updateDayNight(t)` 가 매 프레임 적용합니다.

밤에 불이 켜지는 대상:
- `NIGHT_LAMPS` — `makeStreetLamp` 이 만들 때 자동 등록
- `NIGHT_WINDOW_MATS` — `windowTexture()`가 만든 텍스처에 `userData.isWindow = true` 표식을 달고,
  월드 생성이 끝난 뒤 `scene.traverse` 로 한 번만 훑어 `emissiveMap`을 붙여 모읍니다

> ⚠️ 가로등이 39개라 **`PointLight`를 쓰지 않습니다.** 발광 재질 + 글로우 스프라이트 + 노면 원반으로
> 표현합니다. 광원을 수십 개 켜면 WebGL 광원 한도를 넘고 아이패드에서 프레임이 무너집니다.

## 포인터 입력 (한 번 크게 고친 부분)

`activePointers` 맵으로 손가락을 모두 추적합니다.

- 한 손가락 **톡** → `onPick` (이차곡선 선택)
- 한 손가락 **짧게 끌기** → 카메라 궤도 회전
- 한 손가락 **300ms 이상 누른 채** → 가상 조이스틱 이동 모드 (`touchMoveMode`)
- **두 손가락** → 핀치 확대/축소. 두 번째 손가락이 닿는 순간 걷기·회전을 즉시 중단합니다.
- 마우스(`pointerType === 'mouse'`)는 홀드 이동 모드에서 **제외**합니다.
  (길게 누른 클릭이 흔해서, 포함하면 PC에서 이차곡선 선택이 먹통이 됩니다.)

과거에 실제로 났던 버그들이니 리팩터링할 때 주의하세요.
- 탭/드래그 판정은 **누른 시작점으로부터의 거리**로 해야 합니다. 직전 이벤트와의 델타로 재면
  천천히 길게 끌었을 때 탭으로 오인됩니다.
- HUD 버튼처럼 캔버스 밖에서 시작한 손가락을 뗀 것이면 걷고 있던 손가락을 건드리면 안 됩니다
  (`releasePointer` 의 `tracked` 검사).
- `blur` / `visibilitychange` 안전장치가 없으면 `pointerup`을 놓쳤을 때 캐릭터가 계속 걸어갑니다.

## 실시간 멀티플레이어

`FIREBASE_CONFIG` 가 `null`이 아닐 때만 Firebase compat SDK를 `<script>` 주입으로 동적 로드합니다.
`null`이면 **외부 네트워크 요청이 한 건도 발생하지 않고** 기존과 똑같이 혼자 플레이합니다.

- 경로: `rooms/<room>/players/<studentId>`
- `onDisconnect().remove()` 로 탭을 닫으면 자동 정리
- 0.25초마다 위치 전송 (`broadcastMyPosition`)
- 콘란샵 실내에 있는 동안에는 실내 좌표(먼 구석) 대신 **들어가기 직전의 바깥 위치**를 보냅니다.
  안 그러면 다른 학생 화면에서 지도 밖으로 순간이동한 것처럼 보입니다.
- 화면 상단 `#mp-status` 배지에 접속 인원이 표시됩니다.

> ⚠️ **`FIREBASE_CONFIG` 값을 실수로 `null`로 되돌리지 마세요.** 과거에 파일을 새로 만들어 전달하는
> 과정에서 이 값이 초기화되어 동시접속이 통째로 꺼진 사고가 있었습니다.
> 수정 후에는 `grep projectId index.html` 로 값이 살아있는지 확인하는 습관을 권합니다.

## 검증 방법

three.js CDN에 접근할 수 없는 환경에서도 전체 스크립트가 예외 없이 실행되는지 확인할 수 있습니다.

```bash
cd dev && node test.js
```

`page.route()` 로 `three.min.js` 요청을 `mock-three.js`(Proxy 기반 자동 스텁)로 바꿔치기합니다.
정상 출력: `EARLY_ERRORS: []` / `CONIC_COUNT: 10` / `START_OVERLAY_HIDDEN: true` / `ERRORS: []`

**모의 스텁의 한계**: `THREE.MathUtils.clamp` 같은 헬퍼가 Proxy를 돌려주므로, 그 결과를
숫자로 쓰면 `NaN`이 됩니다. 게임 로직(속도 배율, 밝기 등)에 쓰이는 값은 `Math.max/min`으로
직접 클램프해야 테스트에서 검증이 가능합니다(`clamp01` 참고).
`player.position` 도 Proxy라서 좌표 기반 동작(근접 트리거 등)은 이 하네스로 검증할 수 없습니다.

좌표·배치 검증은 별도 스크립트로 `ROAD_DEFS`와 오브젝트 바운딩 박스를 수치로 비교하는 방식을 써 왔습니다.
(자전거가 도로 위에 놓이는 버그, 인도가 교차로를 막는 버그를 이 방식으로 잡았습니다.)

## 알려진 제약

- 실제 WebGL 렌더링 화면은 개발 환경에서 확인하지 못했습니다. 색감·크기·밝기 밸런스는 배포 후 육안 확인이 필요합니다.
- 지형 배치는 선생님이 그려준 손그림 약도 기반의 근사치이며 실제 축척과 다릅니다.
- 도곡역 건물이 맨 위 도로 위에 살짝 걸쳐 있습니다(오래된 배치, 아직 미수정).
- 마이크 녹음 기능(속삭이는 회랑)은 `https://` 또는 `localhost` 에서만 동작합니다.
