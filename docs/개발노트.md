# 개발 노트 (코드를 수정하기 전에 읽어주세요)

게임은 `src/` 의 ES 모듈 6개와 `dev.html` 로 이루어져 있고, `npm run build` 가 three.js·코드·지도 데이터를
`index.html` 한 파일로 묶습니다. **`index.html` 은 직접 고치지 않습니다.** 개발은 `npm start` 로 `dev.html` 을 열어
합니다(수정 즉시 반영). 배포 전에 반드시 `npm run build` → `npm test` → 커밋.

## 좌표계

- **+x = 동쪽, +z = 남쪽, +y = 위**, 단위 m. 원점 (0,0) = 단대부고 본관 (`data/map.json` 의 `origin`).
- 지도 범위 `map.bounds` ≈ x −748~1372, z −933~947. 플레이어는 이 밖으로 못 나갑니다 (`world.collide`).
- 위도·경도 → 로컬: `x = (lon − 127.05647) × 88,300`, `z = −(lat − 37.49556) × 110,574` (`project()`).
- 전체 지도 캔버스는 `N` 이 위, 화면 y 가 커질수록 z 가 커집니다(남쪽). 플레이어 화살표는 `Math.PI − yaw` 로 돌립니다.
- 베리는 yaw = 0 일 때 +z 를 봅니다. 이동 방향 = `(sin yaw, cos yaw)`.

## 지도 데이터 (`data/map.json`)

`tools/` 로 만듭니다 (README 참고). 게임은 실행 중 지도 API 를 부르지 않습니다.

- `buildings[]` `{p, h, k, n?}` — 폴리곤(평면 좌표 목록), 높이(m; OSM `height`/`building:levels` 없으면 종류·면적으로 추정), 종류
- `roads[]` `{p, w, k, n?, o?, sv?}` — 폭, highway 종류, 일방통행, **스트릿뷰 표본 중 파노라마가 있던 비율(0~1)**
- `areas[]` `{p, k, n?}` — residential(아파트 단지)/school/park/pitch/parking/water …
- `walls[]`, `bikeParking[]`, `lamps[]` — OSM 에 직접 찍힌 담장·거치대·가로등 (이 동네는 거의 없어 게임이 생성)
- `pois[]` — 상점·역 출입구(`k:'exit'`) 등

`build-map.mjs` 는 이전 `map.json` 의 `sv` 를 도로 종류 + 첫 두 점으로 이어 붙여 보존하므로, 지도를 다시 받아도
스트릿뷰 확인을 처음부터 다시 할 필요가 없습니다(새로 생긴 도로만 `streetview-roads.mjs` 가 확인).

## 월드 생성 (`world.js`)

수천 개의 건물·도로·담장을 개별 메시로 두면 프레임이 무너지므로 전부 합쳐서 그립니다.

- `Buf` — 정점·법선·색(·UV)을 쌓아 `BufferGeometry` 하나로 만드는 빌더. `flatTri`(감기 방향 자동 보정), `ribbon`(도로), `stripe`(차선), `quad`(담장 면), `fillPoly`(`ShapeUtils.triangulateShape`).
- 층 순서: 땅(깊이 기록) → 구역 → 도로. 구역·도로는 `depthWrite:false` + `polygonOffset` 으로 땅 위에 덮습니다.
  ⚠️ 땅의 `depthWrite` 를 끄면 하늘 돔이 땅을 덮어버립니다.
- 건물 외벽은 재질 하나(`facadeMat`: 정점색 × 창문 텍스처, `emissiveMap` = 불 켜진 창문 텍스처). 밤에 `setNight` 가 창문 불을 켭니다.
- **담벼락**: 아파트 단지(`residential`)·학교 구역 경계를 `insetRing(p, 5)` 로 5m 안쪽으로 줄인 선을 따라 세웁니다
  (OSM 경계는 보통 도로 중심선이라 그대로 두면 담장이 차도 위에 섭니다). 3m 칸으로 나눠 길(차도·골목·보행로)이
  지나거나 건물이 걸친 칸은 **문으로 비우고**, 남은 칸은 이어 붙여 한 구간으로 그립니다. 충돌용 얇은 사각형도 함께 넣습니다.
- **가로등**: 스트릿뷰 도로(`driveRoads`, 폭 7m 이상) 양쪽 인도에 32m 간격, 최대 1,200개. `InstancedMesh`(기둥·팔·등갓·노면 원반) + `Points`(글로우).
  재질을 공유해 `setNight` 한 번으로 전부 켜집니다. 낮에는 원반·글로우를 `visible=false` 로 아예 안 그립니다.
  ⚠️ `PointLight` 는 쓰지 않습니다 (수백 개면 WebGL 광원 한도·프레임 문제).
- 나무는 `InstancedMesh` 두 개(기둥·수관, 최대 8,000). 공원 면적 비례 + 폭 10m 이상 도로의 가로수.
- 그림자를 드리우는 것: 건물, 나무, 차, 자전거, 베리. 담장·가로등은 그림자 패스 부담을 줄이려 뺐습니다.
  첫 프레임은 셰이더 컴파일로 수십 ms 걸리지만 이후 `render()` 는 1~2ms 입니다.

### 충돌
- `colliders` 격자(20m): 건물 폴리곤, 담장 조각, 나무·가로등 원. `world.collide(pos, R)` 가 밖으로 밀어냅니다.
- `roadGrid`(30m): 도로 이름(`roadAt`), 길 위인지(`onAnyRoad`), 빈자리 찾기(`findOpenSpot`).

## 자동차 · 자전거 (`vehicles.js`)

**자동차는 구글 스트릿뷰로 갈 수 있는 길만 다닙니다.** `driveRoads` = 차량 도로 종류이면서 `sv ≥ 0.5`.
그 꼭짓점을 노드로 묶은 그래프(`buildGraph`, 일방통행은 한 방향 간선만) 위를 `pickNext`(왔던 길 제외, 직진 선호 + 무작위)로
돌아다닙니다. 우측통행: 진행 방향의 오른쪽으로 `lane`(폭/4) 만큼 밀어 그리고, 코너에서 오프셋·회전을 보간합니다.
차체(인스턴스 색)·부품·전조등 빛기둥 세 `InstancedMesh` 로 14대를 그립니다. 전조등 물리(초점거리 슬라이더)는 아직 없습니다.

자전거는 역 출입구(`pois` 의 `exit`) 옆과 단대부고 정문 앞 빈자리에 거치대째 세워 둡니다 (장식, 타기는 아직 없음).

## 밤낮 주기 (`sky.js`)

`DAY 60 → DUSK 30 → NIGHT 60 → DAWN 30` 초 (총 3분). `computeDayFactor(t)` → 1 낮 ~ 0 밤.
하늘 돔(그라디언트 셰이더)·별 돔·해·달은 플레이어를 따라다닙니다(`sky.follow`). 조명 세기·안개·배경색도 여기서 맞춥니다.
`main.js` 가 `night = (1−f)^1.2` 를 `world.setNight`, `cars.setNight` 에 넘깁니다.

## 조작 (`main.js`) — 단붕이 탐험 방식

- 키보드: 회전(←→/AD) + 전진·후진(↑↓/WS), `Shift` 달리기(`RUN_MULT 1.9`). 걷기 `PLAYER_SPEED 11.5 m/s`, 회전 `2.4 rad/s`.
- 포인터: 한 손가락 **톡** → 가까운 랜드마크 카드, **짧게 끌기** → 궤도 카메라 회전, **300ms 이상 누른 채** → 가상 조이스틱,
  **두 손가락** → 핀치 줌. 마우스는 홀드 이동에서 제외(길게 누른 클릭이 흔해서). 탭/드래그 판정은 **누른 시작점 기준 거리**로.
  HUD 버튼에서 뗀 손가락이 걷는 손가락을 건드리지 않도록 `releasePointer` 가 추적 여부를 검사하고, `blur`/`visibilitychange` 에서 전부 초기화합니다.
- 카메라: 걷는 동안 등 뒤로 따라오고, 건물에 가리면 `world.solidAt` 으로 당겨집니다. 줌 5~46.
- 전체 지도는 오른쪽에 항상 표시(`#bigmap`, 1px=1m 지도 이미지를 스케일). `M` 또는 클릭으로 접고, 🗺️ 버튼으로 다시 폅니다.

## 동시접속 (`multiplayer.js`)

`FIREBASE_CONFIG` 가 있으면 compat SDK 를 `<script>` 로 동적 로드. 경로 `rooms/<room>/players/<id>`, `onDisconnect().remove()`,
0.25초마다 위치 전송. 다른 친구는 `createBerry()` 고양이 + 이름표로 보이고 전체 지도에도 파란 점으로 찍힙니다.
**`FIREBASE_CONFIG` 를 `null` 로 되돌리지 마세요** (`docs/멀티플레이어_설정방법.md`).

## 검증

```bash
npm run build && npm test
```
`dev/test.js` 는 빌드된 `index.html` 을 Playwright(SwiftShader WebGL)로 띄워 시작 → 걷기/돌기/달리기 → 지도 접기 → 클릭까지
돌리고 `ERRORS: []`, `MOVED > 0` 을 확인합니다. Firebase 요청은 차단해 "혼자 플레이" 경로를 탑니다.
숨은 탭에서는 `requestAnimationFrame` 이 멈추므로 로딩 단계의 프레임 양보는 `setTimeout` 을 씁니다.
